# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

STM32F103C8T6 (Blue Pill/Cortex-M3) embedded firmware project using STM32 HAL and FreeRTOS. Generated by STM32CubeMX with a custom application framework layer.

**Hardware:** STM32F103C8T6 (64KB Flash, 20KB RAM, Cortex-M3)
**Debugger:** CMSIS-DAP v2.1.1 via SWD
**Build Toolchains:** ARMCC (Keil MDK 5.4) and GCC (arm-none-eabi)

## Project Skills

The project includes three custom skills for embedded development:

| Skill | Purpose |
|-------|---------|
| `embedded-cmake-generator` | Auto-generate CMake build files with ARMCC/GCC support |
| `embedded-flasher` | Flash firmware using OpenOCD (ST-Link, J-Link, CMSIS-DAP) |
| `cmsis-dap-debug` | Debug via OpenOCD with memory/register access |

## Build System

### Recommended Workflow (ARMCC)

```bash
# 1. Generate CMake configuration
python .claude-skills/embedded-cmake-generator/scripts/generate-cmake.py

# 2. Configure and build
mkdir -p build && cd build
cmake .. -G "MinGW Makefiles" -DCMAKE_TOOLCHAIN_FILE=../cmake/armcc-toolchain.cmake
make -j4

# 3. Flash firmware
python ../.claude-skills/embedded-flasher/scripts/flash.py
```

### GCC Toolchain

```bash
# Generate for GCC
python .claude-skills/embedded-cmake-generator/scripts/generate-cmake.py --toolchain gcc

# Build with GCC
cd build && cmake .. -G "MinGW Makefiles" -DCMAKE_TOOLCHAIN_FILE=../cmake/arm-none-eabi-toolchain.cmake
make -j4
```

### Toolchain Configuration

ARMCC toolchain path must be configured in `cmake/armcc-toolchain.cmake`:
```cmake
set(CMAKE_C_COMPILER "D:/APP/Keil/Keil5MDK5.4/ARM/ARMCC/bin/armcc.exe")
# ... adjust to your Keil installation path
```

**Build Artifacts:**
- ARMCC: `build/Project.axf`, `build/Project.bin`, `build/Project.map`
- GCC: `build/Project.elf`, `build/Project.hex`, `build/Project.bin`

**Linker Script:** `STM32F103XX_FLASH.ld` (Flash: 0x08000000, RAM: 0x20000000)

**Scatter File (ARMCC):** `MDK-ARM/Project/Project.sct`

## Flashing and Debugging

### Using Embedded Flasher

```bash
# Default: flash with CMSIS-DAP
python .claude-skills/embedded-flasher/scripts/flash.py

# Specify debugger
python .claude-skills/embedded-flasher/scripts/flash.py --debugger cmsis-dap
python .claude-skills/embedded-flasher/scripts/flash.py --debugger stlink-v2
python .claude-skills/embedded-flasher/scripts/flash.py --debugger jlink

# Adjust speed (kHz)
python .claude-skills/embedded-flasher/scripts/flash.py --speed 2000

# Flash only mode (no reset)
python .claude-skills/embedded-flasher/scripts/flash.py --mode flash
```

### Using CMSIS-DAP Debug

```bash
# Read memory (FLASH)
python .claude-skills/cmsis-dap-debug/scripts/debug.py --read-memory 0x08000000 --count 4

# Read GPIOC ODR register (LED state)
python .claude-skills/cmsis-dap-debug/scripts/debug.py --read-memory 0x4001100C --count 1

# Show all core registers
python .claude-skills/cmsis-dap-debug/scripts/debug.py --show-registers

# Halt target
python .claude-skills/cmsis-dap-debug/scripts/debug.py --halt

# Set breakpoint and step
python .claude-skills/cmsis-dap-debug/scripts/debug.py --set-breakpoint 0x08000100
python .claude-skills/cmsis-dap-debug/scripts/debug.py --resume
python .claude-skills/cmsis-dap-debug/scripts/debug.py --step
```

### Memory Map (STM32F103C8T6)

| Region | Address | Size | Description |
|--------|---------|------|-------------|
| FLASH | 0x08000000 | 64KB | Program memory |
| SRAM | 0x20000000 | 20KB | Data memory |
| Peripherals | 0x40000000 | 512MB | Peripheral registers |

**Common Peripheral Addresses:**
- GPIOA: 0x40010800 (CRL, CRH, IDR, ODR at +0x0C)
- GPIOC: 0x40011000 (LED on PC13, ODR at 0x4001100C)
- USART1: 0x40013800
- USART2: 0x40004400

## Architecture

### Directory Structure

```
Core/           # STM32 HAL generated code (main.c, gpio.c, usart.c, etc.)
Drivers/        # STM32 HAL drivers and CMSIS
Middlewares/    # FreeRTOS kernel
Usr/            # Custom application framework
  ├─ app/       # Application modules (event system, work queue)
  ├─ bsp/       # Board support packages (DWT cycle counter)
  ├─ log/       # Logging utilities
  └─ tool/      # Tools (SEGGER RTT, SEGGER SystemView, tick management)
```

### Custom Framework Layer

**zthread** (`Usr/zthread.h`): Thread abstraction over FreeRTOS/CMSIS-RTOS2
- Provides unified thread API for task creation, scheduling, and waiting
- Supports message queues, semaphores, mutexes, and event groups
- Thread callback pattern: `void (*thread_callback)(void*)`

**Event System** (`Usr/app/event.h`): Event-driven messaging
- Event types: `EVENT_LED_BLINK`, `EVENT_LOG_PRINT`, etc.
- Event priorities: LOW, MEDIUM, HIGH
- Event callbacks registered via `event_register()`

**Work Queue** (`Usr/app/work_queue.h`): Asynchronous task scheduling
- Work modes: SIGNAL (one-shot), LOOP (periodic)
- Work statuses: IDLE, RUNNING, PENDING, DELETED
- Uses FreeRTOS lists and message queues

### Application Entry Points

- `core_main()` - Called from FreeRTOS startup to initialize custom framework
- Event system must be initialized: `event_init()`, `work_queue_init()`
- SEGGER RTT is used for logging/debugging output

## FreeRTOS Configuration

**Key Settings** (`Middlewares/Third_Party/FreeRTOS/Source/include/FreeRTOSConfig.h`):
- `configMAX_PRIORITIES`: 7 (valid priorities: 0-6 in FreeRTOS)
- `configTICK_RATE_HZ`: 1000 (1ms tick)
- `configTOTAL_HEAP_SIZE`: 10KB
- `configAPPLICATION_ALLOCATED_HEAP`: enabled (heap at 0x20005000)

**CMSIS-RTOS V2 Priority Mapping** (critical when creating tasks):
- `osPriorityNone` = 0 → FreeRTOS priority 0
- `osPriorityLow` = 8 → FreeRTOS priority 6
- `osPriorityNormal` = 24 → **EXCEEDS max priority 7, DO NOT USE**
- `osPriorityHigh` = 32 → **EXCEEDS max priority 7, DO NOT USE**

**Correct Task Creation Pattern:**
```c
osThreadAttr_t thread_attr;
memset(&thread_attr, 0, sizeof(osThreadAttr_t));
thread_attr.name = "TaskName";
thread_attr.stack_size = 128 * 4;  // 512 bytes minimum
thread_attr.priority = osPriorityLow;  // Valid: 0-6 maps to FreeRTOS
thread_func_t thread_func = TaskFunction;
osThreadNew(thread_func, NULL, &thread_attr);
```

## Important Notes

- **Toolchain Path**: ARMCC path in `cmake/armcc-toolchain.cmake` must match your Keil installation
- **CubeMX Regeneration**: This is a CubeMX project - preserve `USER CODE` sections when regenerating
- **CMSIS-RTOS V2 Only**: Project uses CMSIS-RTOS2 API, not V1
- **FreeRTOS Port**: ARMCC uses `RVDS/ARM_CM3/port.c`, GCC uses `GCC/ARM_CM3/port.c`
- **Heap Allocation**: Only `heap_4.c` (coalescing) is used; heap starts at `0x20005000`
- **DWT Cycle Counter**: Initialized for performance measurement via `Usr/bsp/dwt_cycle_counter.h`
- **SEGGER RTT**: Provides low-overhead logging
- **GPIO PC13**: Built-in LED (active low: ON = 0, OFF = 1 on Blue Pill)

## Development Workflow

1. **Edit code** in Core/Src, Core/Inc, or Usr/
2. **Add new sources** to `cmake/project_config.cmake` in `C_SOURCES` list
3. **Regenerate CMake** if needed: `python .claude-skills/embedded-cmake-generator/scripts/generate-cmake.py`
4. **Build**: `cd build && make -j4`
5. **Flash**: `python ../.claude-skills/embedded-flasher/scripts/flash.py`
6. **Debug**: Use `cmsis-dap-debug` skill to inspect registers and memory
